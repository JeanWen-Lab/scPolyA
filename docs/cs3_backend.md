# CS3 backend integration

Owned namespace `scpolya_ui.analysis.cs3_backend` exports `capabilities()`, `plan(request)`, `execute(plan, output_dir)`, `status(output_dir)`, `result(output_dir)`.

Three ordinary form operations: `cs3.transform` (atlas points + chain + sizes + binary), `cs3.project` (accounted transform into queryable reference + coverage), `cs3.candidates` (native catalogue/counts + projected atlas + genome). The candidate operation requires counts: no silent omission of cell support. Sequence and stored native risk remain separate. Historical data use `historical_export` with declared provenance; `native_snapshot` requires selected current run binding; `synthetic` is explicitly labelled. No old readiness/authority receipt is accepted or fabricated.

All requests have `schema: scpolya.gui.cs3.v1`, `method`, `mode`, `assembly`, `scope`, `atlas`, `inputs`, `limits`, `native`. Inputs are `{role: {path: ABSOLUTE_REGULAR_FILE, sha256: SHA256}}`; `api.pin(path)` can prepare full bytes/stat pins. Plan snapshots all source bytes/stat and packaged methods. A changed pin invalidates execute. Scope identifies actual population, not presumed cell specificity.

Atlas declaration fields: `name`, `release`, `source_assembly`, `target_assembly`, `source_coordinate_base` (`0based` or `1based`), `coordinate_status` (`documented`, `user_declared`, `operational_inference`), `strand_semantics` (`transcribed_RNA_strand`), `reference_population`, `source_provenance`. PolyA_DB3.2 mouse retains **1-based operational inference**, not confirmed documentation. Coordinate/assembly assertions are declarations retained in reports, never inferred by the GUI.

Transform inputs: `source_table`, `chain`, `source_sizes`, `target_sizes`, `liftover`. Other fields: `format` (`polyadb32` original 16-column file or `normalized_points` TSV with `pas_id/chrom/position/strand`), `accepted_target_contigs` explicit unique list, `chain_direction: {source_side: t, target_side: q}`, `liftover_version` declared pinned version, `limits: {source_rows: positive_int}`. Normalized input values honor the declared base; source-map/status internally normalize to both 0- and 1-based representations with physical ordinal identity. `input.mm9.bed` retains its legacy artifact filename even for another assembly; authoritative build is request/manifest. Canonical and audit binary argv are separately saved. No golden/expected file is read by production.

Project inputs: `status`, `source_map`, `audit_mapped`, `chain`, `source_sizes`, `target_sizes`, `source_coverage`, `sequence_contract`, `fasta`, `fai`, `catalogue`, `transform_manifest`, `transform_contract`, `sequence_sizes`. `transform_receipt` is a pin to the successful transform `index.json`, binding every reused output and chain/size input. `source_build` and `target_build` must match declarations; `assessed_target_contigs` is explicit. `limits` has `source_rows`, `audit_rows`, `chain_blocks`, `catalogue_rows`. `source_coverage` JSON retains `source_sha256`, `assessment: complete_named_source_payload`, `assessed_source_contigs`. The frozen mouse projection conservatively keeps chrM unassessable. Source loss without a localizable target is reported separately; it is never assigned a fabricated target interval.

Candidates inputs: `catalogue`, `counts`, `reference`, `reference_contract`, `coverage`, `fasta`, `fai`, `target_sizes`, `sequence_sizes`, `sequence_contract`, `projection_receipt`; optional `labels`. Projection receipt is successful project `index.json`, binding the three reference products and atlas declaration. `pair_semantics` is `unknown` or `unique_pairs_required`; `limits` has `catalogue_rows`, `count_rows`, `reference_rows`, `label_rows`. Catalogue TSV requires `peak_name/chrom/start/end/strand/mispriming_pass` in native schema, counts requires `peak_name/cell_barcode/umi_count`, labels requires `barcode/pass_qc`. Optional gene/transcript/stored risk fields retain NA. FASTA is uncompressed with exact FAI, and all contig names/lengths equal sequence_sizes. Chain target_sizes retain official chain header pins. Actual evaluated catalogue/reference/exclusion contigs must belong to both size tables with equal lengths; otherwise REFUSAL, without aliases or dropped rows. Sequence contract JSON requires `assembly`, `fasta_path`, `fai_path`, `fasta_sha256`, `fai_sha256`, `source_provenance`, `identity_scope`.

For synthetic/historical candidate requests `native` is `{classification: synthetic|historical_export, source_provenance: text}` with no invented invocation ID. For native snapshots pass the GUI `run_evidence_service.discover` binding unchanged: classification `new_snapshot_of_current_retained_files`, run_record_id/run_id/workspace_id, view_root/original_root, config/config_hash, invocation_id/invocation pin, path_mappings and optional namespace_manifest pin. Latest succeeded invocation/config is checked before and after analysis; both scientific tables must be within the selected root. This is a snapshot association, not proof that retained files were generated at execution time.

Import has no scientific side effects. `capabilities` does not import scientific methods. The caller launches worker with `TMPDIR=SQLITE_TMPDIR=TASK_ROOT/scratch` **before Python starts**; creates task parent/scratch and passes fresh nonexistent `TASK_ROOT/analysis`. GUI supervisor enforces 2 CPU, 16 GiB, swap 0, wall 7200s, disk 20 GiB. Backend checks row bounds and writes `status.json`, `REFUSAL.json` on failure, retains partial output and never retries. Existing output directories are refused without writing into them. Source/algorithm SHA snapshots plus full extraction diffs are inside the package.

CLI source-checkout entry (use the GUI Python interpreter with its existing dependencies):

```bash
TMPDIR=/absolute/task/scratch SQLITE_TMPDIR=/absolute/task/scratch /absolute/venv/bin/python -I -B /absolute/checkout/scpolya_ui/analysis/cs3_backend/worker.py plan --request /absolute/request.json --write /absolute/task/plan.json
TMPDIR=/absolute/task/scratch SQLITE_TMPDIR=/absolute/task/scratch /absolute/venv/bin/python -I -B /absolute/checkout/scpolya_ui/analysis/cs3_backend/worker.py execute --plan /absolute/task/plan.json --output /absolute/task/analysis
```

The dedicated worker bootstraps only its own checkout, so no package install/PYTHONPATH is needed. A module invocation with `-I -m` requires an installed UI package; the existing pyproject only packages agent/diff namespaces, so use the explicit worker path for GUI integration.

`index.json` is the common bounded summary/tables/artifacts envelope, scientific files live under `data/`. Relative result paths and hashes are verified on `result`. The full `assessment.jsonl` preserves all sites, candidate universe retains stored-true AND assessable absent only; candidates.tsv includes locus `chrom:start1-end1` and original genomic interval/strand. Zero detection is no recorded positive detection, not biological zero; unknown UMI summation is NA. Complete detected-cell/peak sort and the frozen exploratory primary/risk shortlist (each up to 3 distinct literal genes + 3 null-gene records) are exported separately. No BAM/native pipeline, network download or old RESULT/expected input.

Frozen helper nuance: ambiguous/truncated windows with an observed definite positive signal retain `positive_lower_bound` and reason. They are not clean/full-window positives. Without sufficient positive evidence they remain `not_assessable`, never imputed zero. Motif scans upstream -50..-1 for AAUAAA/AUUAAA; A-richness is >=12 A in downstream +1..+20.

R2 narrow contract: Atlas declarations also require `mitochondrial_contig: chrM` and `mitochondrial_policy: ucsc_chrM_conservative_v1`. V1 conservatively excludes chrM, refuses other declared mitochondrial naming/semantics and explicit MT/chrMT/M contig names, and never guesses aliases. This is a declared supported convention, not general arbitrary-genome support. Project requests additionally require read-only `normalized_source_coordinate_base: 1based`: source_position in reference.tsv is normalized 1-based; raw atlas base remains in source_coordinate_declaration. Point semantics and summary atlas labels come from that validated declaration without an independent-acceptance claim. Other-joint-QC selection audit rows retain original universe order; ranked candidates/strata retain the historical sort.

The direct worker verifies recorded source entries (including the UI package initializer and API) before importing any project package for execute. G2 additionally requires exact clean HEAD/tree, verifies pinned operator scripts and Python/liftOver binary bytes before project imports, and uses fresh task roots. A successful computation plus nonzero parity comparison writes PARITY-CHECK with computation_status=succeeded and classification=parity_mismatch; it does not write ATTEMPT-FAILURE. The separate verifier adds parsed exact-order primary/risk, full selection-audit and selected-record comparisons to the original20 bytewise files.
